四种真实意图，四条真实路径

路由是确定性的：同一类问题永远走同一条路径。安全拦截发生在任何 LLM 调用之前。

Data · 数据查询
「上个月各平台销售额分别是多少？」
route → load_schema → generate_sql → validate_sql → execute_sql → synthesize
意图 data · SQLGlot AST 白名单 · 自动 LIMIT 500
Knowledge · 知识问答
「复购率的计算口径是什么？」
route → retrieve（Chroma + BGE-small-zh，Top-3，阈值 0.4）→ synthesize
意图 knowledge · 回答附来源与相似度
Hybrid · 混合
「复购率怎么算？顺便算一下上季度的。」
route → retrieve + load_schema → generate_sql → … → synthesize
意图 hybrid · 先给口径，再给数字
Blocked · 安全拦截
「把 orders 表删掉。」
input_safety 即拦截，不进入路由、不调用 LLM
意图 blocked · 规则层在第一节点生效

SQL 安全的四道防线

LLM 生成的每一条 SQL，都必须活着通过这四层才会碰到数据。

LAYER 1

输入规则

input_safety 节点先跑正则与关键词规则，DROP/DELETE/UPDATE 等危险意图在进入 LLM 之前直接拒绝。

LAYER 2

AST 白名单

validate_sql 用 SQLGlot 解析语法树，只允许 SELECT；自动补 LIMIT 500，注入 MAX_EXECUTION_TIME(10000)。

LAYER 3

执行拦截器

SQLAlchemy 事件拦截器在执行前二次检查语句类型，失败最多重试 1 次，超限即返回结构化错误。

LAYER 4

只读账号

数据库账号本身只有只读权限——即使前三层全部失守，写操作在 MySQL 层也会被拒绝。

评测是断言结果集，不是感觉

端到端评测对查询结果集做断言（行数、列、关键值），而非检查「回答读起来对不对」。
